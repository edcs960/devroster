# ADR 0002 — 역할 파이프라인을 세션으로 묶기

- 상태: Accepted (2026-10-15). v2 Workflow 엔진에 구현 완료 (2026-10-16). 운영 투입은 v2 승격 후.
- 결정: 연속된 역할을 세션으로 묶어 세션마다 AI CLI를 한 번 실행한다. 세션 안에서는 역할을 순서대로 수행하되 결과·상태·재진입은 역할(노드) 단위로 유지한다. 세션 사이 인계는 기존 파일·snapshot 기반 산출물로만 한다.

| 세션 | 역할 (기본 순서) | 쓰기 | 종료 후 |
|---|---|---|---|
| 분석 `analysis` | Planner → FMEA Expert → Architect → DBA | 읽기 전용 | 승인 (설정, 기본 ON) |
| 디자인 `design` | UX/UI → Designer | 읽기 전용 | 승인 (설정, 기본 OFF) |
| 개발 `develop` | Developer Common → Frontend/Backend/Infra | 코드 (구성 역할 정책 합집합) | — |
| 검증 `verify` | QA → Test Automation → Security → Reviewer | 테스트 경로 (Test Automation) | 이슈 시 재진입, 개발 세션은 이전 대화 이어쓰기 |
| 문서 `docs` | Tech Writer (앞에 graphify 조회 노드) | 문서 경로, `docs/wiki/` | 검증 노드 |

- 세부 결정:
  - 대상: DevRoster **v2 Workflow 엔진만** (E1). 레거시 orchestrator는 수정하지 않고 v2 승격 후 은퇴한다.
  - 표현: v2 role 노드의 `session` 필드. 같은 세션 노드 사이에는 조건·합류 노드만 올 수 있고, 같은 세션은 module·provider·model이 같아야 한다.
  - 활성화: 프로젝트 roster `session_mode`(기본 off, 필요한 프로젝트만 켬)와 `gates`. v2 승격 비교(zero_diff)는 레거시 데이터 이관만 검사하므로 세션 활성화와 무관하다(2026-10-16 정정).
  - 역할 순서: FMEA Expert를 Planner 다음으로(D2). v2 node id에는 번호가 없어 id 재부여 없이 순서만 바꾼다. 레거시 실행 데이터는 변환하지 않는다.
  - 역할 지시 대체(D1): 워크스페이스 `.agent-dev/roles/<role>.md`만 허용하고 snapshot에 경로·digest를 고정한다. 저장소 `agent/`·`AGENTS.md`는 계속 무시한다.
  - 문서 세션 분리(D4): 도구 노드는 세션 구간 안에 둘 수 없으므로 Tech Writer를 별도 세션으로 두고, 그 앞에 연결 ID `graphify` 조회 노드(선택)를 자동 삽입한다.
  - 이어쓰기(W4): 최근 재진입 대상이 속한 세션만 이전 Claude 대화를 `--resume`한다. 하위 검증 세션은 새 대화. Codex는 `exec resume`에 샌드박스 옵션이 없어 새 세션.
  - 위키: 프로젝트 `docs/wiki/`(코드베이스 지도, 교훈, ADR 색인). 세션 실행의 각 역할은 "위키 변경 제안"만 남기고 Tech Writer가 검증 후 반영한다.
  - 역할 추가: 프로젝트 roster(순서·커스텀 역할)로 한다. 세션은 역할→세션 기본 매핑과 커스텀 역할 권한(code → 개발, 그 외 → 앞 역할 세션)으로 자동 배정된다.
- 근거: 한 세션에서 13~15단계를 이어가면 컨텍스트 압축으로 결정이 소실된다. 역할마다 실행하면 격리는 최대지만 재로딩 비용이 크다. 권한과 사람 승인 지점이 같은 단위가 세션 경계다. 검증은 개발 맥락과 분리되어 독립 검증이 된다.
- 비용: 세션 안에서는 역할별 쓰기 구분이 약해진다(합집합 정책). 이어쓰기된 개발 세션이 검증 결과를 합리화할 위험이 남는다. 교차 검증은 여전히 역할마다 실행된다.
- 재검토: 세션 구간 형식 위반이 반복되거나 분석 세션 컨텍스트 압축이 잦으면 세션을 더 나눈다. 새 역할이 기존 세션 권한과 맞지 않으면(배포, 운영 DB 접근) 별도 ADR.
- 이력: 최초안(2026-10-15)은 레거시 orchestrator에 4세션을 구현하고 step id를 재부여하는 안이었다. v2 조사 후 대상 엔진을 v2로 바꾸면서 폐기했다(개정 1 계획서 보존).
