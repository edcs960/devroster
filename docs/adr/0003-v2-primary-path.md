# ADR 0003 — 승인 기반 엔진(v2)을 개발 작업의 주 경로로 사용

- 상태: Accepted (2026-10-24).
- 근거: 샘플 새 프로젝트로 기획서 → 명세·화면 승인 → 인계 → v2 실행 → 검증 통과까지 실증, ADR 0001(로컬 workflow), ADR 0002(역할 세션)

## 배경

- 목표는 로컬에서, 구독 중인 AI CLI로, 기획서를 기반으로 개발하는 에이전트다. 기획서 흐름(Studio → 인계 → 승인 → 실행)은 승인 기반 엔진으로 들어간다.
- 실증에서 막힌 지점: 새 프로젝트의 v2 실행·게시가 기본 꺼짐, 문서 경로 기본값이 없어 Tech Writer에서 복구 불가 blocked, 완료가 GitHub PR과 필수 CI를 전제.

## 결정

1. **새 기능 개발은 v2 기준으로 한다.** 레거시 파이프라인은 기존 작업 마무리·호환·버그 수정만 받는다.
2. **(A) 작업 완료는 로컬 완료가 기본이다.** 검증 통과와 코드 검토를 마친 작업은 게시 단계에서 작업 브랜치에 커밋하고, 사용자의 완료 승인 때 기본 브랜치를 그 커밋으로 빠른 병합(fast-forward)한다. 원격 push는 사용자가 한다. GitHub PR·필수 CI 검사는 프로필 `completion.mode = "github"`으로 고르는 선택 방식이다. 이 결정 이전에 승인된 snapshot은 필수 CI 검사가 지정된 경우에만 GitHub 방식을 유지한다.
3. **새 프로젝트는 v2 실행·게시를 기본 허용한다.** 레거시 자료를 옮겨 온 작업 공간만 기존 승격 절차(read → dual_write → execute → publish)를 따른다. 백업 복원본은 계속 실행을 끈 채로 연다.
4. **새 프로젝트 기본 설정은 v2 흐름을 막지 않는다.** 테스트 경로(`tests`, `src/test`)와 문서 경로(`docs`, `README.md`)를 기본으로 두고, 프리셋 수정 허용 경로에 문서 경로를 포함한다. 경로가 없는 구조화 역할(Test Automation·Tech Writer)은 수정안 없이 통과한다.
5. **(B) 진행 중인 레거시 작업은 레거시로 마무리한다.** 새 작업부터 v2로 시작한다. 레거시 제거 절차(릴리스 gate 2회 → 백업 → 읽기 전용 → 별도 승인 후 제거)는 실제 프로젝트 기능의 v2 실증 뒤 시작한다.
6. **(C) 세션 묶음 실행은 새 프로젝트 기본값으로 켠다.** 연속된 역할을 세션마다 AI 1회로 실행하며, 작은 기능 실측에서 입력 토큰이 약 절반이었다. 설정 화면에서 프로젝트마다 끌 수 있고, 기존 프로젝트의 설정은 바꾸지 않는다. 구간 형식이 어긋나면 같은 대화에서 한 번 재요청하고, 그래도 실패하면 역할별로 실행한다.
7. **설계 문서**: 기능 작업은 구현 전 `docs/`에 설계 문서를 두고, 대화로 정한 정책 결정은 ADR 또는 설계 문서로 옮긴다. 버그 수정은 이슈목록·변경이력으로 충분하다.

## 결과

- 좋은 점: 기획서 흐름 하나로 개발이 이어지고, 로컬만으로 작업을 닫을 수 있다. 승인·snapshot·worktree 격리·검증 근거는 그대로 쓴다.
- 비용: 로컬 완료는 원격 CI를 대체하지 않는다(등록한 검증 명령의 품질에 의존). 기본 브랜치가 작업 시작 후 바뀌면 빠른 병합을 거부하고 다시 검증을 요구한다. 두 엔진이 공존하는 동안 공통 기능의 양쪽 호환을 유지한다.
- 재검토: 팀 단위 원격 협업(PR 리뷰)이 주 사용 방식이 되면 결정 2를 다시 본다.

## 후속 결정: 레거시 엔진 제거 (2026-10-29)

- 근거: 실제 프로젝트 저장소 복제본으로 v2 흐름을 끝까지 실증한 뒤 v2 적용과 레거시 제거를 결정했다. 진행 중이던 레거시 작업은 먼저 완료 또는 취소로 닫고, 작업 공간 데이터를 백업한 뒤 제거했다.
- 제거: 레거시 CLI(`dev-pipeline`, `shell`, `ask`, `new-task`, `auto`, `mascot`, `discord-listen`, `feedback-watch` 등), 오케스트레이터(`agent_dev/pipeline`), 레거시 품질 검사(`agent_dev/quality`), 레거시 큐·상태 저장소, 레거시 실행기 전환(`runners/factory`·`failover`·`agent_runner`·`openai_agent`·`handoff`), Discord 명령 리스너, 데스크톱·웹 마스코트.
- 유지: v2가 쓰는 공용 기반(`core`, CLI 실행기 `runners/*_cli`, `storage/process_registry`, `scm/git_publish`, 설정 `config/settings`), 레거시 자료 가져오기(`refactor migrate/compare`)와 레거시 배치 작업 공간의 설정 해석. 읽기 전용 gate(릴리스 2회 관찰)는 레거시 쓰기 경로 자체를 지웠으므로 적용하지 않았다.
- `run`·`verify`·`resume`·`complete`·`status`는 `task` 명령의 짧은 형태로 남는다. 그 밖의 옛 명령은 "Unknown command"로 끝난다.
