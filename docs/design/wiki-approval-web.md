# 위키 승인 웹 화면 설계

- 날짜: 2026-11-02
- 배경: 위키 항목(재발 방지·테스트 실행 지식)의 승인·반려·폐기가 CLI(`devroster knowledge approve|reject|retire`)로만 가능했다(04 진행현황 9번).
- 범위: 기존 `WikiKnowledge` 규칙을 그대로 쓰는 웹 화면 `/wiki`. 제안·개정(propose/revise)은 Tech Writer와 CLI 경로로 남긴다.

## 동작

| 화면 요소 | 내용 | 사용하는 adapter |
|---|---|---|
| 목록 | 프로젝트별 항목. 상태 필터(승인 대기·운영 중·반려·폐기), 페이지(lessons·testing), 근거 파일, 근거 확인 상태 | `WikiKnowledge.items` |
| 승인 | 승인 대기 항목만. 승인자 이름 필수. 근거가 바뀌었거나 해결 근거가 없으면 adapter 오류를 그대로 보여 준다 | `approve` |
| 반려 | 승인 대기 항목만. 처리자 이름 필수 | `reject` |
| 폐기 | 운영 중 항목만. 이유·처리자 필수 | `retire` |
| 열람본 갱신 | 상태를 바꾼 뒤 이 작업 공간의 프로젝트면 Markdown 열람본(`docs/wiki` 또는 설정한 `wiki_dir`)을 다시 만든다. 실패해도 상태 변경은 유지하고 오류를 함께 보여 준다 | `render` |

## 경계

- 정본은 프로젝트 DB다. 화면은 DB를 직접 고치지 않고 adapter 메서드만 부른다. 승인 근거 검사·상태 전이·이벤트 기록은 CLI와 같다.
- 쓰기 요청은 다른 화면과 같은 `LocalWeb` 경계(로컬 주소, 같은 출처, 화면 토큰, JSON 1MB)를 거친다.
- 처리자 이름은 화면 입력값이다. 로컬 단일 사용자 도구라 인증된 사용자 신원이 아니다(CLI의 `--actor`와 같은 수준).
