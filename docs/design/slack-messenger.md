# 슬랙 메신저 연동 설계

- 날짜: 2026-11-04
- 요청: 피클(사용자 AI 에이전트)이 슬랙 채널에 남긴 요청을 DevRoster가 계속 확인해 작업을 진행한다. 외부 메신저 연계를 설정하는 화면을 만든다.
- 사용자 결정: 승인도 슬랙에서 받는다. 리스너는 앱 안과 터미널 명령 둘 다. 피클 ↔ 슬랙 연결은 사용자가 한다.

## 1. 구조

```text
피클 → 슬랙 채널 ──(conversations.history 주기 조회)──▶ 리스너 ──▶ 명령 해석 ──▶ 기존 DevRoster 명령
                 ◀──────(chat.postMessage, 스레드 답글)────────────── 결과·진행 알림
```

- 로컬 앱은 공개 주소가 없어 슬랙 Events API(밀어 넣기)를 받을 수 없다. 리스너가 Web API로 채널을 주기적으로 조회한다(기본 15초). 표준 라이브러리 HTTP만 쓴다.
- 명령은 새 실행 경로를 만들지 않고 기존 CLI 명령(`command_line.execute`)과 에이전트 작업실 백그라운드 실행(`AgentConsole`), Studio 작업(`StudioJobs`)을 그대로 호출한다. 승인·snapshot·검증 규칙은 웹·CLI와 같다.

## 2. 신뢰 경계

| 항목 | 규칙 |
|---|---|
| 채널 | 설정한 채널 1개만 조회 |
| 작성자 | 허용한 슬랙 사용자 ID 또는 봇 ID만 처리. 피클이 사용자 계정으로 올리든 앱으로 올리든 허용 목록으로 구분 |
| 메시지 종류 | 새 메시지만. 편집·삭제·입장·스레드 답글은 무시 |
| 시작 지점 | 처음 켤 때 현재 시각을 기준점으로 저장. 과거 메시지를 다시 실행하지 않음 |
| 중복 | 메시지 ts를 처리 기록에 남기고, 실행 명령은 요청 ID `slack-<채널>-<ts>`로 한 번만 실행 |
| 명령별 허용 | 요청·상태·실행·승인을 따로 켜고 끔. 승인은 기본 꺼짐 |
| 승인 기록 | 승인자를 `slack:<사용자 ID>`로 남김. 슬랙 승인도 DevRoster 승인 기록과 같은 규칙(근거·버전 확인)을 거침 |
| 메시지 내용 | 신뢰하지 않는 데이터. 명령 문법에 맞는 부분만 인수로 쓰고, 요청 본문은 Studio 기획서 초안으로만 들어감 |
| 토큰 | 이 컴퓨터의 공통 인증 저장소(`credentials/shared`, 0600)에만 저장. 화면·DB·내보내기·답글에 나오지 않음 |
| 동시 실행 | 리스너 하나만 동작. 상태 파일의 heartbeat로 두 번째 리스너(앱과 터미널 동시 실행)를 거부 |

## 3. 명령

첫 줄로 판단한다. 맨 앞 봇 멘션(`<@U…>`)과 설정한 머리말은 떼고 읽는다.

| 명령 | 예 | 동작 | 방식 |
|---|---|---|---|
| 도움말 | `도움말`, `help` | 명령 목록 | 즉시 답글 |
| 요청 | `요청 회원 탈퇴 기능` + 다음 줄부터 본문 | Studio 프로젝트를 만들고 명세 생성 시작. 끝나면 결과 답글 | Studio 작업 |
| 상태 | `상태`, `상태 TASK-001` | 작업 목록 요약 또는 한 작업 설명 | 즉시 |
| 실행 | `실행 TASK-001`, `재개 TASK-001`, `검증 TASK-001` | 승인된 작업 실행. 끝나면 결과 답글 | 백그라운드 |
| 승인 | `승인 설계 DESIGN-1 1`, `승인 계획 PLAN-1`, `승인 단계 TASK-001 approve-analysis` | 설계·계획·Workflow 승인 단계 승인 | 즉시 |

영어 명령(`help`, `request`, `status`, `run`, `resume`, `verify`, `approve design|plan|step`)도 받는다. 모르는 명령에는 도움말 안내로 답한다.

## 3-1. 작업 상태 알림

- 리스너가 조회할 때마다 작업 목록의 상태를 지난 조회와 비교해, 바뀐 작업마다 `TASK-001 제목: 이전 → 지금`을 채널에 올린다(상태 이름은 화면과 같은 한국어).
- 슬랙 `실행`·`재개`·`검증`으로 시작한 작업은 그 명령의 스레드에, 나머지는 채널에 올린다. 완료·취소되면 스레드 연결을 지운다.
- 승인 단계에서 멈추면 단계 이름과 함께 `승인 단계 <작업> <단계>` 명령을 안내한다(승인 명령이 꺼져 있으면 화면 안내).
- 알림을 처음 켤 때는 현재 상태만 기록하고 보내지 않는다. 한 번에 최대 20건. 설정의 "작업 상태 알림"으로 끈다(기본 켬).

## 4. 저장 위치

| 내용 | 위치 |
|---|---|
| 설정(비밀 아님) | `<설정 폴더>/config/messenger.json` |
| 처리 상태(기준점, 처리한 ts, 진행 중 작업, 작업별 마지막 상태·스레드, 최근 기록, heartbeat) | `<설정 폴더>/data/messenger-state.json` |
| 봇 토큰 | 공통 인증 저장소 연결 `messenger-slack`, 키 `SLACK_BOT_TOKEN` |

DB 스키마는 바꾸지 않는다. 실행 명령의 중복 방지는 기존 command 기록을 쓴다.

## 5. 화면 `/messengers` (외부 메신저 연결)

- 슬랙 앱 준비 안내: 봇 토큰 범위 `channels:history`(비공개 채널은 `groups:history`), `chat:write`. 봇을 채널에 초대.
- 입력: 봇 토큰(저장·삭제만, 다시 보이지 않음), 채널 ID, 허용 사용자 ID, 허용 봇 ID, 머리말, 조회 주기(10~300초), 명령별 허용, 사용 여부.
- 연결 검사: `auth.test`와 `conversations.info`로 토큰과 채널 접근 확인.
- 리스너: 상태(동작 중 여부, 마지막 조회, 마지막 오류, 처리 건수), 시작·중지, 최근 처리 기록 20건.

## 6. 실행 형태

- 앱: `devroster app`이 켜질 때 설정이 "사용"이면 리스너 스레드를 시작한다. 화면에서 시작·중지한다.
- 터미널: `devroster messenger listen`(Ctrl+C로 종료), `devroster messenger status`, `devroster messenger test`.
