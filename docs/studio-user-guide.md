# 기획·화면 검토 Studio 사용 가이드

기획서를 바탕으로 명세서와 목업을 만들고, 화면의 요소별 의견을 처리해 개발할 화면을 확정한다.

## 실행

```sh
devroster studio --root /path/to/my-project
```

| 항목 | 값 |
|---|---|
| 브라우저 | `http://127.0.0.1:8767/studio` |
| 포트 변경 | `devroster studio --port 8870` |
| 다른 프로젝트 | 패키지 설치 후 `devroster studio --root /path/to/project`. 이미 `devroster init`한 프로젝트 안에서는 `devroster studio`만 실행한다 |

**화면 구성**

- 작업 상태와 실행은 **작업실**(`/agent`) 한 화면에서 본다.
- 이전 **개발 현황** 주소(`/dashboard`)는 작업실로 이동한다.
- 읽기 전용 대시보드는 `devroster dashboard` 명령으로 따로 연다.

**설정 연결**

- 도구·모델·실행파일은 상단 **AI·환경 설정** 또는 `devroster setup --web --root PROJECT`에서 저장한다.
- 저장 후 Studio를 새로 열거나 새로고침하면 기본값을 사용한다.
- 프로젝트·개발환경 준비는 [설정 사용 가이드](setup-user-guide.md)를 참고한다.

## 1. 기획서 작성

**작성 순서**

1. **새 프로젝트**에서 이름을 입력한다.
2. **기획서 템플릿 다운로드** 또는 **편집기에 템플릿 넣기**를 사용한다. 작성된 `.md`, `.markdown`, `.txt`는 **MD·TXT 파일 가져오기**로 연다.
3. 사용자, 기능, 화면, 입력값·업무 규칙, 완료 기준을 적는다. 모르는 규칙은 ‘미정’으로 남긴다.
4. **기획서 저장** → 생성 도구 선택 → **명세서 생성**.

**입력 제한과 준비물**

- UTF-8 파일, 500KB·120,000자 이하. 형식/길이 오류는 입력을 유지한 채 안내한다.
- CLI는 Codex·Claude·Gemini를 설치하고 로그인한다. API는 OpenAI·Claude·Gemini·호환/로컬 서버를 설정하며 CLI 설치가 필요하지 않다. [다중 AI 연결 안내](multi-ai-user-guide.md)를 따른다.
- API는 지원하는 모델 이름을 등록해야 한다. CLI 모델 이름을 비우면 도구 기본 모델을 사용한다.

> **주의**: 생성 시 입력은 선택한 AI 서비스로 전달된다. 비밀번호·API 키·실제 고객 개인정보는 넣지 않는다.

**명세서가 만들어지는 방식**

- 명세서는 두 단계로 만든다. 먼저 요구사항·화면·확인 질문을 정리하고(1/5), 이어서 문서를 네 묶음(기획·요구, 화면·데이터, 설계, 검증·관리)으로 나눠 쓴다(2/5~5/5).
- 진행 표시에 지금 단계가 보인다.
- 묶음 하나가 형식에 맞지 않으면 그 묶음만 한 번 더 쓰고, 그래도 실패하면 그 문서들을 ‘생성 실패’로 표시한 채 나머지를 저장한다.
- 생성에 수 분 걸릴 수 있다.
- **생성 중단**은 결과 반영을 중단한다. CLI 프로세스는 종료하며, API로 이미 전달된 요청의 원격 처리·과금은 제공자가 결정한다.
- 실패하면 기존 자료를 유지하며 자동으로 유료 재시도하지 않는다.

## 2. 명세서 검토

**요구사항과 문서**

- 추출한 요구사항에서 `REQ-*`, 원문 근거, 수용 기준을 확인하고 수정한다.
- 왼쪽 문서 목록에서 명세서 22종을 읽고 편집한다.
- **미리보기**는 제목·목록·표·코드 블록을 표시한다.

**확인 질문과 확정**

- 확인 질문에 답하고 **수정 저장**한다.
- 답변에 따른 문서 변경이 필요하면 **저장한 답변으로 명세서 다시 생성**을 사용하거나 직접 문서를 수정한다.
- 답변·문서 내용이 일치하는지 확인한 뒤 **명세서 확정** → **목업 생성**.

**문서 하나만 다시 만들기**

- 문서 하나만 고치려면 그 문서를 열고 **이 문서 다시 생성**을 누른다(고칠 점은 선택 입력).
- 요구사항·화면 목록과 다른 문서는 그대로 두고 그 문서만 새 버전으로 쓴다.
- ‘생성 실패’로 표시된 문서도 같은 방법으로 다시 만든다.
- 개발기획서는 입력한 기획서 원문이라 다시 생성하지 않는다.

**다이어그램**

- 시스템·시퀀스·클래스 다이어그램과 프로세스정의서에는 Mermaid 코드 블록(```` ```mermaid ````)이 들어간다.
- 미리보기에서는 코드와 **코드 복사** 버튼이 보이고, GitHub·내보낸 Markdown·Mermaid 편집기에 붙여 넣으면 그림으로 보인다.
- 화면 보안 정책(인라인 스타일 차단) 때문에 앱 안에서는 그림으로 그리지 않는다.

**내려받기와 버전**

- **22종 ZIP 다운로드**는 저장된 현재 명세서를 제공한다.
- **명세 버전**으로 이전 버전을 읽을 수 있다.

> **주의**: 확인 질문에 답하지 않았거나 수정이 저장되지 않았다면 확정할 수 없다.

- 수정·재생성은 새 버전으로 저장하며 기존 확정 자료를 덮어쓰지 않는다.
- 기획서를 변경하면 새 명세서·목업을 검토해야 한다.

## 3. 화면 검토

| 기능 | 사용법 |
|---|---|
| **화면 선택** | 왼쪽 화면 목록에서 선택 |
| **요소 의견** | **요소에 의견 남기기** → 제목·입력창·버튼 등을 클릭 → 오른쪽에서 코멘트 작성 |
| **키보드 선택** | 요소로 Tab 이동 후 Enter/Space |
| **요구사항 확인** | 선택한 요소의 오른쪽 패널에서 연결된 `REQ-*` 확인 |
| **샘플 동작** | **화면 조작하기**에서 입력·화면 이동·샘플 처리 안내 확인 |
| **모바일 확인** | **화면 크기**에서 모바일 선택 |
| **직접 문구 변경** | 선택 요소 → **요소 문구 직접 수정** → 새 버전 저장 |
| **의견 반영** | **의견 반영해 재생성** → 새 목업을 실제로 검토하고 코멘트 처리 |
| **의견 처리** | 코멘트 처리 메모 작성 → **처리 완료**. 필요하면 **다시 검토** |
| **화면 확정** | 미해결 의견 처리 후 **이 화면 확정** |
| **확정 후 변경** | **새 검토 버전**을 만들거나 재생성한 뒤 다시 검토 |

**의견과 확정 규칙**

- 미해결 코멘트는 새 버전에 이어진다.
- 삭제된 요소에 남은 의견은 별도 목록으로 표시하며 처리 전에는 확정을 막는다.
- AI가 의견을 반영했다고 주장해도 코멘트는 자동으로 처리 완료되지 않는다.
- 이전 버전의 의견·확정 근거는 읽기 전용으로 보존한다.

**목업의 범위**

- 목업은 구조화된 화면 요소로 렌더링한다.
- 샘플 조작은 실제 서버 저장이나 업무 규칙 구현을 대신하지 않는다.
- 자유로운 HTML/CSS 코드 생성, 드래그 편집, Word/PDF 입력, 여러 사용자 실시간 공동 편집은 이번 범위에 포함하지 않는다.

## 4. 개발 인계

모든 화면 확정 + 미해결 의견 0개 → **확정된 개발 인계 ZIP 다운로드**.

| 파일 | 용도 |
|---|---|
| `documents/*.md` | 개발기획서와 명세서 22종 |
| `specifications.json` | 요구사항·원문 근거·질문 답변·화면 관계 |
| `mockup/index.html` | 브라우저에서 여는 확정 목업 (인터넷 연결 없이 열 수 있음) |
| `mockup/mock.json` | 요소 ID와 요구사항 연결 |
| `decisions.json` | 버전·해시·의견 처리·화면 확정 근거 |
| `development-handoff.md` | 기존 설계 승인 흐름에 입력할 통합 자료 |
| `tasks.json` | 화면별 작업과 화면 외 요구사항 작업 |
| `README.md` | 개발 계획 등록 순서 |

기존 초기화한 개발 프로젝트에서 ZIP을 푼 후, 새 설계·계획 ID를 정해 실행한다:

```sh
devroster design refine PROJECT-ID DESIGN-ID development-handoff.md
devroster design approve DESIGN-ID 1
devroster plan create PROJECT-ID PLAN-ID DESIGN-ID 1 tasks.json
devroster plan approve PLAN-ID
```

> **주의**: runner/profile/test gate를 확인한 뒤 실제 task 실행을 별도로 시작한다. Studio 확정은 기존 실행 권한·배포 승인을 자동 부여하지 않는다.

## 저장과 복구

| 실행 위치 | Studio 상태 |
|---|---|
| 초기화한 다른 프로젝트 | `PROJECT/.agent-dev/studio/studio.db` |
| 초기화 없이 `--root PROJECT` | `PROJECT/.agent-dev/studio/studio.db` |

**저장**

- 작업 상태 DB(`state.db`)와 분리해 저장한다.
- `devroster backup create /safe/project.zip --root PROJECT`(format 2)은 canonical DB와 Studio DB를 SQLite backup API로 함께 담는다.
- Studio만 사용한 작업 공간도 백업할 수 있다.

> **주의**: 원본 DB와 `-wal` 파일을 실행 중에 단순 복사하지 않는다.

**복구**

- 복구는 `devroster backup restore BUNDLE.zip NEW_PROJECT_DIR`로 `.agent-dev`가 없는 새 폴더에 한다.
- 이전 format 1(canonical만) 백업도 복원된다.
- 복원본의 승인·실행 상태 처리는 [다른 프로젝트에서 사용하기](reuse.md) 8장을 따른다.
- 중단된 생성은 lease 만료(최대 약 45초) 후 실패로 표시되고 다시 생성할 수 있다.

## 오류와 해결

| 안내 | 해결 |
|---|---|
| CLI 설치·로그인·모델 설정 확인 | 로컬 CLI 설치와 로그인, 지원 모델 확인 후 명시적으로 다시 생성 |
| 생성 결과 형식 검증 실패 | 기획서의 기능·화면을 구체화하거나 범위를 나눠 다시 생성 |
| 다른 변경이 저장됨 | 저장 전 편집 내용을 복사해 보관하고 프로젝트를 다시 불러온 뒤 적용 |
| 최신 목업에서 작업 | 버전 선택에서 현재 목업으로 이동 |
| 미해결 의견/삭제된 요소 의견 | 처리 메모를 남겨 해결한 뒤 확정 |
| 해시 불일치 | 수정된 DB를 계속 사용하지 말고 별도 백업과 비교해 복구 |

**동시 실행과 접속 범위**

- 생성은 한 프로젝트에 하나, 저장소 전체에 최대 두 작업까지 허용한다.
- 서버는 loopback 주소에서만 접속하며 Studio 변경 요청은 같은 origin과 세션 토큰을 확인한다.

## 작업별 AI 선택

- 프로젝트 설정에서 고정/균형형 자동 정책과 후보 모델·지원 강도를 등록한다.
- Studio의 **프로젝트의 선택 정책 적용**을 켜면 그 정책을 사용하고, 해제하면 이번 생성의 모델·추론 강도를 직접 정한다.
- 선택은 생성 시작 시 확정되며 최근 생성·변경 이력에서 확인할 수 있다.
- 설정·예시·기록 위치는 [설정 사용 가이드](setup-user-guide.md)를 참고한다.
