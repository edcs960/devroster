# 웹 개발 도우미 사용 가이드

웹에서 설정·기획·Workflow 편집과 승인 작업 실행까지 사용할 수 있다. 작업 요청 등록만으로 개발이 시작되지는 않으며, 실행 전 입력·범위 확인과 기존 승인 조건이 필요하다.

## 새 웹 작업실 빠른 시작

```sh
devroster studio --root /path/to/my-project
```

`http://127.0.0.1:8767/agent` → 왼쪽 **☰** → 원하는 화면. 포트는 설정이나 `--port`에 따라 달라진다. 메뉴는 현재 화면을 표시하고 Escape로 닫으며 버튼으로 포커스를 돌려준다.

1. **프로젝트 설정**: 최상위·프론트·백 폴더, AI 실행기·모델·자동 effort, 인증 환경변수, 검증 명령을 저장하고 진단한다. 컨텍스트 전달량과 Ponytail 호환 지침도 선택할 수 있다.
2. **기획·화면**: Markdown/TXT 기획서를 저장하고 명세서·목업을 생성한다. 요소에 의견을 달고 확정한 뒤 개발로 인계한다.
3. **개발 흐름**: 프리셋 사용 또는 복제해서 편집. 단계를 선택하면 역할·모듈·경로·모델·추론 강도·독립 검토·디자인·도구를 폼으로 지정한다. 연결의 시작/도착·조건도 설정한다. 그래프의 단계는 끌거나 선택 후 화살표 키(Shift: 크게)로 옮기고 **자동 배치**로 정리한다. 배치는 실행 순서에 영향을 주지 않는다. 저장한 Workflow를 열면 두 버전을 골라 **버전 비교**로 단계·연결·설정·배치 차이를 본다. 수정한 초안은 저장한 뒤 적용한다.
4. **작업실**: 작업을 고르면 제목 옆에 상태에 맞는 주 행동 버튼 하나가 나온다(실행 준비 → **실행**, 차단됨 → **차단 원인 보기**, AI 실행 대기 → **이어서 실행**, 검증 중 → **검증 실행**, 게시 준비 → **검토 상태 확인**, 사용자 검토 → **변경 검토 열기**, 승인 대기 → **대기 이유 보기**, 완료·취소 → **상세 보기**). 나머지 기능은 **⋯** 메뉴에 있고, 지금 상태에서 쓸 수 없는 기능은 흐리게 표시되며 이유가 함께 나온다. 조회 기능(상태·차단 원인, 사용량, 상세)은 바로 결과를 보여준다. 변경하는 기능은 **실행 전 확인**을 거쳐 **확인한 내용으로 실행**을 눌러야 요청되며, 게시·완료처럼 추가 입력이 필요한 기능은 입력 칸이 먼저 열린다. 백업·업그레이드 같은 프로젝트 기능은 화면 아래 **프로젝트 전체 기능**에서 검색한다. 실행 현황(단계 수, 현재 AI 도구·모델·선택 이유, 대기 이유, 다음에 할 일, 실행 기록, 예상 비용)은 화면을 보는 동안 3초(숨겨지면 30초)마다 갱신하고, 끝난 작업은 갱신을 멈춘다. 실행/재개는 승인된 설계·계획·snapshot을 사용한다. 중간 승인 단계는 개발 흐름의 Task ID 상태 조회에서 처리한다. 작은 수정은 작업 목록 위의 **빠른 수정**에서 모듈·제목·고칠 내용만 입력한다. 실행 전 확인에 만들어질 설계 문서와 흐름(개발 → QA → 코드 검토 → 검증)·수정 허용 경로가 나오고, **확인한 내용으로 실행**을 누르면 그 확인이 설계·계획 승인으로 기록된 뒤 바로 실행된다. 모듈 하나, 그 모듈의 수정 허용 경로와 검증 명령으로 고정된다. CLI는 `devroster task quick <모듈> <제목> <설명.md>`(미리 보기는 `--dry-run`). 실행 현황의 **실시간 로그**는 AI 도구가 읽고 바꾼 파일, 실행한 명령, 메시지를 실행 중에 1초마다 이어서 보여준다(Codex·Claude. Gemini는 단계가 끝난 뒤 결과만). 모델의 내부 추론은 기록하지 않고 비밀값은 가린다. 로그는 작업 폴더의 `.attempts`에 2MB까지 남고 30일이 지나면 지워진다. 작업을 완료하거나 `devroster worktree prune`으로 작업 폴더를 정리하면 로그는 작업 폴더 밖으로 옮겨져 그때부터 30일 동안 더 볼 수 있다.
5. **소스 탐색**: 모듈 선택 → 폴더 펼치기/검색 → 코드·줄 보기. 검색은 **파일 이름** 또는 **코드 내용**(한글·대소문자 구분·폴더 지정)을 고른다. 한 번에 파일 50개·1000줄·결과 100개·2초까지 확인하고 **더 찾기**로 이어간다. 1MiB 초과·바이너리·비밀·범위 밖 파일은 건너뛴다. 결과를 누르면 해당 줄로 이동하며, 검색 후 파일이 바뀌었으면 다시 검색하라고 안내한다. 파일 화면의 **영향·테스트 후보**는 관계 그래프(Graphify)와 이름 규칙으로 찾은 후보이며 실제 실행 범위나 필수 테스트를 확정하지 않는다. 관계 그래프가 없으면 내장 인덱스가 Python(`import`)·JavaScript/TypeScript(`import`·`require`, 상대 경로)·Java(`import`)의 파일 간 import 관계로 찾는다. 외부 패키지·동적 import·리플렉션은 따라가지 않고, 바뀐 파일만 다시 읽는다. 소스 탐색·검색은 macOS·Linux·Windows에서 동작하며, 심볼릭 링크와 Windows 정션은 따라가지 않는다.
6. **변경 검토**: 작업실의 **변경 검토 열기**(`/review?task=TASK-ID`)에서 파일별 변경·근거·코멘트를 보고 코드 검토를 결정한다. 승인은 처리하지 않은 코멘트가 없고 현재 소스로 검증이 통과했을 때만 가능하다. 설정에 등록한 미리보기 서비스가 있으면 **실제 화면 미리보기**에서 서비스를 시작·연결하고 화면을 캡처해 요소에 코멘트를 남기고 화면 검토를 결정한다. 캡처에는 설치된 Node Playwright와 Chrome 경로가 필요하다(`DEVROSTER_PLAYWRIGHT_MODULE`, `DEVROSTER_BROWSER_EXECUTABLE`; 자동 설치하지 않음). DevRoster가 다시 시작되면 이전에 띄운 서비스는 종료된 것으로 표시되므로 다시 시작한다.
7. **추적성·변경**: `/traceability`에서 요구사항·수용 기준과 테스트·검증 근거 연결을 보고, `/changes`에서 요구사항 변경 영향과 후속 작업을 확인한다. 근거 연결률은 연결 정도를 보여줄 뿐 기능 보장을 뜻하지 않는다.
8. **도구 연결·디자인 참고**: 설치된 서버/공식 주소와 인증 환경변수 이름·자료 범위를 등록한다. 목록 확인 후 실제 읽기를 검사한다. Stitch는 원본을 수정하지 않는다. Figma/Stitch 참조를 Studio 프로젝트 또는 Workflow에 적용한다.

| 상황 | 처리 |
|---|---|
| 실행 전에 입력 변경 | 다시 입력·범위 확인 |
| 실행 요청 취소 | 실행 이력에서 취소 → 작업 상태 확인 → 작업 취소 또는 재개; 기존 task lease는 최대 300초 후 만료될 수 있음 |
| Workflow 검사 오류 | 단계 ID·조건 양쪽 경로·필수 역할·등록 gate ID 확인 |
| 프로젝트 적용 | 이후 생성하는 snapshot에 반영; 기존 승인 snapshot은 유지 |
| Graphify 미설치 | 파일 조회는 계속 사용, 격리 환경에 고정 버전 설치 후 PATH 등록 |
| 연결 상태 partial | 목록만 확인됨; 범위/인증/필수 입력을 확인하고 실제 읽기 검사 |
| Browser MCP | 현재 자료 읽기는 차단, 도구 목록 진단만 제공 |
| OAuth 만료 | 등록 client ID와 지원 계정으로 다시 인증 |
| 예상 비용이 "가격표 미설정" | 프로젝트 설정 → 개발·검증 환경 → 예상 비용에 모델 가격(100만 토큰당)을 입력. 값은 직접 입력한 추정치이며 실제 청구액·구독 잔여량이 아님 |
| 비용 "미산정 N회" | 사용량을 보고하지 않은 호출, 모델 미기록, 가격 미등록은 0으로 세지 않고 미산정으로 표시 |
| 예산 알림 비율 도달 | 실행 기록에 알림만 남기고 실행을 멈추지 않음 |

CLI 예시:

```sh
devroster workflow presets --root /path/to/my-project
devroster workflow list --project PROJECT-ID --root /path/to/my-project
devroster integration catalog --root /path/to/my-project
devroster integration doctor --root /path/to/my-project
devroster source modules --root /path/to/my-project
devroster source tree --module source --root /path/to/my-project
devroster source file --module source --path src/app.py --root /path/to/my-project
devroster source build --module source --root /path/to/my-project
devroster source search "저장" --mode content --path src --root /path/to/my-project
devroster source search "저장" --mode content --cursor NEXT_CURSOR --root /path/to/my-project
devroster source impact --module source --path src/app.py --root /path/to/my-project
```

`source search`의 `next_cursor`를 `--cursor`로 넘기면 다른 터미널 실행에서도 이어서 찾는다. 이를 위해 첫 CLI 검색이 `.agent-dev/source-search.key`(소유자만 읽기)를 만든다. 웹 화면은 이 파일을 만들지 않으며, 웹의 이어 찾기는 서버를 다시 시작하면 처음부터 검색해야 한다.

코드 파일은 읽기 전용이며 등록 범위 밖·비밀 파일·심볼릭 링크는 표시하지 않는다. 그래프는 코드 근거와 추론을 구분하며 실제 실행·전체 영향 범위를 확정하는 자료는 아니다. 내보내기는 credential/비밀 값/기존 자료 scope를 제외하고, 새 프로젝트에서 재연결한다.

## 세션 묶음 실행

연속된 역할을 세션으로 묶어 세션마다 AI를 한 번만 실행한다. 결과와 재실행은 역할 단위로 기록된다. 새 프로젝트는 기본으로 켜져 있고, 설정에서 프로젝트마다 끌 수 있다(ADR 0003).

| 순서 | 할 일 |
|---|---|
| 1 | 설정 → 개발 역할 → **세션 묶음 실행** 체크 |
| 2 | 승인 위치 선택: 분석 세션 뒤(기본 켜짐), 디자인 세션 뒤 |
| 3 | **설정 저장** → 프로젝트 Workflow가 세션 구성으로 다시 만들어짐 |
| 4 | 작업 실행 후 작업 화면의 **세션** 카드에서 진행 확인. 승인 대기면 승인한 뒤 이어서 실행 |

| 세션 | 역할 |
|---|---|
| 분석 | Planner, FMEA Expert, Architect, DBA |
| 디자인 | UX/UI, Designer |
| 개발 | Developer Common, Frontend/Backend/Infra Developer |
| 검증 | QA, Test Automation Developer, Security Reviewer, Reviewer |
| 문서 | Tech Writer |

- 역할 순서를 바꿔 같은 세션이 떨어져 있으면 "검증 2"처럼 따로 묶인다. 각 역할 옆에 소속 세션이 표시된다.
- 개발 흐름 편집기에서 역할 단계의 **세션** 값을 바꿔 직접 묶을 수 있다. 같은 세션 역할 사이에는 승인·검증·도구 단계를 둘 수 없다.
- 검증에서 문제가 나와 개발로 돌아가면 개발 세션은 이전 대화를 이어서 수정하고(Claude), 검증은 새로 시작한다.
- 문서 세션 앞에서 코드 그래프를 조회하려면 외부 도구 연결에서 Graphify를 연결 ID `graphify`로 등록한다. 등록하지 않으면 이 단계는 건너뛴다. 이 단계는 그래프를 조회만 한다. 프로젝트 루트에 `graphify-out/graph.json`이 있으면 `devroster task complete`가 완료 처리 뒤 `graphify update <프로젝트 루트>`(LLM 없이 코드만 재추출)를 자동 실행하고 결과를 `code_graph`(`updated`/`skipped`/`failed`)로 돌려준다. 갱신 실패는 완료를 막지 않는다. DevRoster 밖에서 코드를 바꿨다면 `graphify update .`를 직접 실행한다.
- Tech Writer가 프로젝트 위키 `docs/wiki/`를 갱신하려면 모듈 허용 경로에 `docs/`가 있어야 한다.
- 끄면 기존처럼 역할마다 따로 실행한다.

## 위키 승인

메뉴 **설정·자료 → 위키 승인**(`/wiki`)에서 작업 중 제안된 재발 방지·테스트 실행 지식을 검토한다. 승인한 항목만 다음 작업의 역할 프롬프트에 들어간다.

- 상단에 처리자 이름을 넣고, **승인 대기** 항목을 승인하거나 반려한다. **운영 중** 항목은 이유를 적어 폐기한다.
- 근거 파일이 바뀌었거나 해결 근거(해결된 이슈, 통과한 단계 출력·테스트)가 없으면 승인이 거부된다. 이때는 `devroster knowledge revise`로 근거를 고친 새 버전을 만든다.
- 상태를 바꾸면 이 작업 공간 프로젝트의 Markdown 열람본(`docs/wiki/` 또는 설정한 위키 경로)도 다시 만든다. 열람본은 직접 고치지 않는다.
- 새 항목 제안과 개정은 Tech Writer 단계나 `devroster knowledge propose|revise`로 한다.

## 슬랙으로 요청·승인 (외부 메신저)

메뉴 **설정·자료 → 외부 메신저**(`/messengers`)에서 슬랙 채널을 연결하면, 그 채널에 남긴 요청을 DevRoster가 주기적으로 확인해 처리하고 같은 스레드에 결과를 답한다. 피클 같은 AI 에이전트가 대신 메시지를 올려도 된다.

1. 슬랙 앱을 만들어 봇 토큰 범위 `channels:history`(비공개 채널은 `groups:history`)와 `chat:write`를 주고, 봇을 채널에 초대한다.
2. 화면에서 봇 토큰(`xoxb-`)을 저장하고, 채널 ID와 허용할 사용자 ID(U…)·봇 ID(B…)를 넣는다. 허용 목록에 없는 작성자의 메시지는 무시한다.
3. 쓸 명령을 고르고 **사용**을 켠 뒤 저장 → **연결 검사** → **시작**. 앱을 다시 켜면 리스너도 자동으로 시작한다. 화면 없이 쓰려면 `devroster messenger listen`.
4. (선택) 조회 주기를 기다리지 않고 바로 답하게 하려면 슬랙 앱 설정에서 **Socket Mode**를 켜고 `connections:write` 범위의 앱 수준 토큰(`xapp-`)을 만든다. **Event Subscriptions**에 봇 이벤트 `message.channels`(비공개 채널은 `message.groups`)를 추가하고 앱을 다시 설치한다. 화면에 앱 토큰을 저장하고 **Socket Mode로 바로 받기**를 켜면, 새 메시지가 오는 즉시 채널을 읽어 처리한다. 공인 IP나 열린 포트는 필요 없다. 연결이 끊기면 다시 연결하는 동안 조회 주기대로 확인한다.

| 슬랙 메시지 | 동작 |
|---|---|
| `요청 <제목>` + 다음 줄부터 내용 | Studio 기획서를 만들고 명세 생성. 끝나면 알림 |
| `상태`, `상태 TASK-001` | 작업 목록 또는 한 작업 상태 |
| `실행`·`재개`·`검증 TASK-001` | 승인된 작업 진행. 끝나면 결과 알림 |
| `승인 설계 <ID> <버전>`, `승인 계획 <ID>`, `승인 단계 <작업 ID> <단계 ID>` | 승인(기본 꺼짐). 승인자는 `slack:<사용자 ID>`로 기록 |
| `도움말` | 명령 목록 |

- 작업 상태가 바뀌면 채널에 알린다(설정에서 끌 수 있음). 슬랙에서 시작한 작업은 그 스레드에 올리고, 승인 단계에서 멈추면 승인 명령을 함께 안내한다.
- 처음 켤 때 이전 채널 기록은 실행하지 않는다. 메시지마다 한 번만 처리한다.
- 리스너는 앱과 터미널 중 한 곳에서만 동작한다.
- 명세 확인·화면 승인·인계(설계·계획 만들기)는 Studio 화면에서 한다. 만들어진 설계·계획은 슬랙에서 승인할 수 있다.
- 설계: [슬랙 메신저 연동 설계](design/slack-messenger.md)

## 실행 품질

- **프롬프트 크기**: AI를 부를 때마다 프롬프트의 항목별 글자 수(승인된 설계, 위키, 스킬, 이전 단계 결과 등)를 기록한다. 작업실 실행 현황의 **프롬프트 크기** 카드에 전체 크기와 큰 항목이 나온다. 크기만 남기고 내용은 남기지 않으며, 프롬프트를 자르지는 않는다.
- **검증 명령 도구(Claude)**: Claude의 코드 역할은 작업 중에 `run_project_check` 도구로 프로젝트에 승인된 검증 명령(테스트·lint·빌드)을 실행해 결과를 볼 수 있다. 명령·폴더·시간 제한은 승인된 계획 그대로이고 모델은 검증 이름만 고른다(단계당 10회). Codex는 자체 샌드박스 셸이 있어 붙이지 않고, Gemini는 아직 지원하지 않는다.
- **테스트 먼저(`test-first`) 흐름**: 기획 → 자동화 테스트 → 개발 전 실패 확인 → 개발 → QA → 코드 검토 → 검증. 자동화 테스트 역할이 수용 기준으로 테스트를 먼저 쓰고, 개발 전에 검증을 돌려 테스트가 **실패하는지** 확인한다. 이미 통과하면 기준을 확인하지 못하는 테스트로 보고 자동화 테스트 역할로 되돌린다.

## 다른 프로젝트에서 사용

[설치·운영 가이드](reuse.md)에 따라 패키지 설치·workspace 초기화·승인 실행을 진행한다. 프로젝트 폴더에서 아래 명령으로 조회 화면을 연다.

```sh
devroster dashboard --port 8766
```

기본 주소는 `http://127.0.0.1:8766/`이다. 현황 화면의 명령 복사 버튼은 실행하지 않는다. ☰ → 에이전트 작업실에서 승인·실행할 수 있다.

여러 프로젝트에 같은 AI 기본값·MCP 연결을 쓰려면 설정 화면의 **공통 설정**(`/settings`)을 연다. 공통값은 프로젝트에서 "반영"할 때만 적용되고, 화면은 항목마다 실제 값과 출처(공통값·프로젝트 지정·기본값)를 보여준다. 저장 위치 이전도 같은 화면에서 사전 점검 후 실행한다. 끝난 작업의 작업 폴더(git worktree)는 같은 화면의 **작업 폴더 정리**에서 병합된 것만 확인 후 지운다. 자세한 내용은 [설정 가이드](setup-user-guide.md)의 7절을 참고한다.
