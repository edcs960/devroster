# 14 Reviewer Phase

## 목적

변경 결과가 요구사항, 안정성, 보안성, 유지보수성, 성능, 테스트 관점에서 배포 가능한지 최종 검토한다.

## 적용 역할

- `AGENTS.md`
- `agent/reviewer.md`
- 모든 이전 phase 결과

## 입력

- 변경 파일 목록
- 구현 요약
- QA 결과
- 검증 명령 결과
- 요구사항/수용 기준
- `Design Reference Context`가 있는 경우 참고 화면, Frontend 구현 결과, QA의 참고 화면 비교 결과

## 수행 절차

1. 요구사항 충족 여부를 확인한다.
2. 실제 장애나 유지보수 비용으로 이어질 수 있는 문제를 우선 검토한다.
3. 보안, 권한, 입력 검증, 데이터 무결성, 성능, 테스트 누락을 확인한다.
4. `Design Reference Context`가 있으면 참고 화면과 구현 화면의 차이가 요구사항 위반인지, 기존 디자인 시스템에 맞춘 의도적 조정인지 검토한다.
5. 심각도별 발견 사항과 수정 제안을 작성한다.
6. 최종 승인 여부를 판단한다.
