# Vibe Feature Development Prompt

이 프롬프트는 프로젝트 기능 개발을 바이브코딩 방식으로 진행할 때 사용한다.

사용자는 역할 파일과 산출물을 매번 첨부하지 않는다. Agent가 `AGENTS.md`, `agent/*`, 프로필 문서, 코드베이스를 직접 확인하고 개발을 진행한다.

## 사용 방법

```txt
$dev-pipeline
아래 기능을 바이브코딩 방식으로 개발해줘.

기능:
[개발할 기능 또는 수정할 내용]

기대 동작:
[사용자가 확인하고 싶은 결과]

제약:
[있으면 작성, 없으면 생략]
```

## Agent 진행 규칙

1. `AGENTS.md`를 최상위 규칙으로 확인한다.
2. 요청 성격에 맞는 역할 파일을 자동으로 확인한다.
3. 도메인 업무 규칙은 도메인 전문가 역할 파일(있을 때)과 방법론 참고 문서를 기준으로 검토한다.
4. 화면, API, DB, 권한, 테스트 영향이 있으면 관련 산출물을 자동으로 확인한다.
5. 구현 단계에서는 `agent/developer.md`를 공통 기준으로 적용한다.
6. Frontend, Backend, Infra, DB 작업은 해당 전문 역할을 함께 적용한다.
7. 가능한 경우 lint/test/build를 실행한다.
8. 최종 응답에는 사용자가 직접 확인할 테스트 포인트를 포함한다.

## 자동 참조 대상

### 역할

- `agent/planner.md`
- `agent/architect.md`
- `agent/dba.md`
- `agent/ux-ui.md`
- `agent/designer.md`
- `agent/developer.md`
- `agent/developer-frontend.md`
- `agent/developer-backend.md`
- `agent/developer-infra.md`
- `agent/qa.md`
- `agent/reviewer.md`

### 산출물

- 프로필 문서: 역할별 필수 문서(`role_required_context`)

### 개발환경

- 프로필 문서: 공통 개발 표준(`context_files`)

## 사용자 피드백 프롬프트

구현 결과를 확인한 뒤에는 아래처럼 자연어로 전달한다.

```txt
방금 구현한 기능을 테스트했는데 아래 수정이 필요해.

확인한 화면/기능:
[예: 편집 화면 트리 우클릭 액션 추가]

문제:
[예: 액션그룹 하위 액션 생성 후 리스트가 갱신되지 않음]

기대 동작:
[예: 저장 성공 후 트리와 우측 상세 패널이 즉시 갱신되어야 함]

추가 참고:
[스크린샷, 에러 메시지, 재현 절차가 있으면 작성]
```

Agent는 피드백 유형을 분류하고 필요한 역할 단계부터 다시 진행한다.

## 완료 기준

- 요구사항이 구현되어야 한다.
- 기존 구조와 컨벤션을 유지해야 한다.
- 도메인 방법론과 산출물의 정책을 위반하지 않아야 한다.
- DB 무결성, 이력, 권한, 대량 트리 성능 리스크가 검토되어야 한다.
- 화면은 로딩/에러/빈/성공 상태가 고려되어야 한다.
- 가능한 경우 lint/test/build를 실행해야 한다.
- 변경 파일, 검증 결과, 사용자 확인 포인트를 요약해야 한다.
