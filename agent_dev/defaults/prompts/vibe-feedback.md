# Vibe Coding Feedback Prompt

구현 결과를 사용자가 확인한 뒤 수정사항을 전달할 때 사용한다.

역할 파일과 산출물은 다시 첨부하지 않는다. Agent가 이전 작업 맥락, `AGENTS.md`, 역할 파일, 산출물, 개발환경 문서, 코드베이스를 확인해 필요한 단계부터 다시 진행한다.

```txt
방금 구현한 기능을 테스트했는데 아래 수정이 필요해.

확인한 화면/기능:
[예: 편집 화면 - 하위 항목 생성]

재현 절차:
1. [첫 번째 동작]
2. [두 번째 동작]
3. [문제가 발생한 지점]

문제:
[예: 저장 후 트리에는 액션이 보이지 않지만 새로고침하면 표시됨]

기대 동작:
[예: 저장 성공 직후 트리와 우측 상세 패널이 즉시 갱신되어야 함]

추가 참고:
[스크린샷, 콘솔 에러, API 응답, 테스트 계정 등 필요한 정보]
```

## Agent 처리 기준

- 작은 버그는 Developer → QA → Reviewer 순서로 처리한다.
- 화면 흐름 문제는 UX/UI → Designer → Developer 순서로 재검토한다.
- API/DB/권한 문제가 있으면 Architect → DBA → Developer 순서로 재검토한다.
- 도메인 방법론과 충돌하면 도메인 전문가 검토를 먼저 수행한다.
- 수정 후에는 변경 파일, 검증 결과, 사용자가 다시 확인할 테스트 포인트를 요약한다.
