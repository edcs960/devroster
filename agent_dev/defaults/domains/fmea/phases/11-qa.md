# 11 QA Phase

## 목적

구현 결과가 요구사항, 수용 기준, 사용자 시나리오, 예외 흐름을 만족하는지 검증한다.

## 적용 역할

- `AGENTS.md`
- `agent/qa.md`
- Planner, UX/UI, Designer, Developer 결과

## 입력

- 모든 이전 phase 결과
- 변경 파일 목록
- verification-report
- 테스트 시나리오 문서
- `Design Reference Context`가 있는 경우 UX/UI, Designer, Frontend Developer가 확인한 참고 화면과 구현 기준

## 수행 절차

1. Planner 수용 기준과 구현 결과를 매핑한다.
2. 정상/예외/경계값 테스트를 작성한다.
3. 권한, 데이터 저장/삭제, API 실패, 네트워크 오류, 대량 데이터, 접근성을 검증한다.
4. `Design Reference Context`가 있으면 실제 구현 화면과 참고 화면을 비교해 상태 표현, 반응형, 접근성, 정보 구조 차이를 검증한다.
5. 화면 관련 기능은 수용 기준별 화면 시나리오와 대응 e2e spec을 정리한다. 실제 브라우저 실측은 DevRoster 검증 단계의 e2e 명령이 수행한다. 역할 실행 안에서 브라우저 실측을 하지 못한 것은 issue나 재진입 사유가 아니며, Not Tested에 "검증 단계 e2e로 확인"으로 남긴다. 대응 spec이 없는 시나리오는 Test Automation 자동화 후보로 넘긴다. e2e 명령과 spec 위치는 프로젝트 설정의 검증 명령과 프론트엔드 저장소 구성을 따른다.
6. 자동화 테스트 후보와 수동 테스트 체크리스트를 정리한다.
7. QA 통과 여부와 차단 이슈를 판단한다.
