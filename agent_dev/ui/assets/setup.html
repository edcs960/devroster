설정 신뢰

이 프로젝트 폴더의 DevRoster 설정(.agent-dev)은 이 컴퓨터에서 만든 것이 아닙니다. 저장소와 함께 받은 설정에는 다른 사람이 적은 명령이 들어 있을 수 있어, 신뢰하기 전에는 아래 명령을 실행하지 않습니다(작업 승인·실행·검증, Studio 생성, 로그인 확인, MCP 연결, 미리보기, 훅). 내용을 확인한 뒤 신뢰하세요.

설정에 실행할 명령이 없습니다.

    신뢰는 이 컴퓨터의 DevRoster 관리 폴더에만 저장되고 저장소에는 남지 않습니다. 훅은 신뢰한 뒤에도 따로 승인해야 실행됩니다.

    01

    프로젝트 폴더

    최상위 폴더와 프론트·백엔드 위치를 지정하세요. 하나의 저장소와 분리된 저장소 모두 사용할 수 있습니다.

    다른 폴더를 선택했다면 ‘설정 불러오기’를 눌러주세요. 없는 폴더도 아래 생성 옵션으로 준비할 수 있습니다.

    한글·영문·숫자·하이픈·밑줄. 기존 프로젝트 ID는 고정됩니다.

    02

    사용할 AI

    이 프로젝트에서 쓸 AI 도구와 순서를 고릅니다. 로그인·모델·추론 강도·API 키는 AI 도구 메뉴에서 모든 프로젝트가 함께 관리합니다.

    사용할 AI 도구 · 순서

    체크한 도구만 이 프로젝트의 작업에 쓰입니다. 위에 있는 도구가 먼저 쓰이고, 첫 번째 도구가 기획·목업 생성의 기본 도구입니다. 저장하면 다음에 승인하는 작업부터 적용됩니다.

      이 프로젝트는 아직 자체 AI 설정을 씁니다. 공통 AI 도구로 전환하면 이 프로젝트의 현재 도구·모델·강도를 그대로 유지하면서 AI 도구 메뉴에서 함께 관리합니다.

      작업별 선택 미리보기

      아래 작업 제목과 단계를 기준으로 선택합니다. 실제 실행에서는 작업 범위와 위험 신호도 함께 확인합니다.

      컨텍스트·토큰 절약 (선택)

      원문은 보존하고 도구 결과의 전달량을 조정합니다. 절감 지표는 실제 사용량과 추정치를 구분합니다.

      내장 호환 지침입니다. 외부 스킬을 설치하거나 AGENTS.md를 변경하지 않으며 필수 검증은 유지합니다.

      CLI는 각 카드의 로그인 안내를 따르세요. API는 모델과 인증 환경변수를 등록합니다. API 도구는 기획·명세·목업 생성에, 개발 CLI는 파일 수정에 사용합니다. 저장·진단은 유료 AI 호출을 하지 않습니다. Gemini 인증 확인은 로컬 준비 상태이며 실제 계정 접근은 실행 시 확인합니다.
      03

      개발 역할

      작업에 참여할 역할과 실행 순서를 정합니다. 기본 역할은 내장 AGENTS.md 기준이며 순서만 바꿀 수 있고 삭제할 수 없습니다.

      FMEA를 고르면 FMEA Expert를 순서에 넣고, 일반으로 바꾸면 뺍니다. 선택 역할은 언제든 직접 추가·삭제할 수 있습니다.

      실행 순서

        선택한 역할

        역할을 선택하면 이름·권한과 수정 가능한 지시를 확인할 수 있습니다.

        + 새 역할 만들기

        권한은 만든 뒤 바꿀 수 없습니다. 다른 권한이 필요하면 새 역할을 만들어주세요. 내장 역할 지시는 바꿀 수 없습니다.

        세션 묶음 실행

        새 프로젝트는 기본으로 켜져 있습니다. 세션마다 AI를 한 번만 실행해 역할별로 따로 실행할 때보다 입력 토큰이 약 절반으로 줄어듭니다(작은 기능 기준 실측). 끄면 역할마다 따로 실행해 역할 간 독립성이 높아지는 대신 사용량과 시간이 늘어납니다. 세션 안의 역할은 결과를 역할별로 기록하고, 문제가 생기면 해당 역할부터 다시 실행합니다.

        역할별 스킬

        저장소마다 기술 스택에 맞는 스킬 묶음을 고르세요. 설치한 스킬은 Claude Code와 Codex가 함께 쓰고, 개발 작업에는 각 역할에 맞는 스킬만 전달됩니다. 검토해 버전을 고정한 공개 스킬만 사용합니다.

        프로젝트 AI 규칙

        이 프로젝트에만 적용되는 규칙입니다. .ai/rules에 저장되고, 개발 작업을 승인할 때 고정되어 어떤 AI 도구(CLI·API)에든 같은 내용으로 전달됩니다. Studio의 명세서·목업 생성에도 적용됩니다. 동기화는 CLAUDE.md·AGENTS.md·GEMINI.md와 스킬 연결(.claude/skills, .agents/skills)을 맞춥니다. DevRoster 기본 규칙은 함께 적용되며 수정할 수 없습니다. 규칙으로 쓰기 범위·승인·검증을 바꿀 수는 없습니다.

          프로젝트 스킬 .ai/skills

          폴더마다 SKILL.md(앞부분에 description, 선택 사항 roles)를 둡니다. 역할에 맞는 스킬이 모든 AI에 전달되고, Studio 생성에는 roles가 비었거나 studio인 스킬이 쓰입니다.

            프로젝트 훅 .ai/hooks/hooks.json

            정해진 순간에 DevRoster가 직접 실행하는 명령입니다. 어떤 AI를 쓰든 똑같이 동작합니다. 코드 수정 직후·검증 전·게시 전 훅은 실패하면 그 단계를 막고, 나머지는 결과만 기록합니다. 저장소에 들어 있는 명령이므로 내용을 확인하고 승인해야 실행되며, 바뀌면 다시 승인해야 합니다.

              AI에 전달되는 프로젝트 규칙 미리보기
              

              역할이나 순서를 바꾸고 저장하면 프로젝트 Workflow가 이 순서로 다시 만들어집니다. 역할을 바꾸지 않으면 개발 흐름에서 적용한 Workflow를 유지합니다.
              

              04
              개발·검증 환경
              수정할 수 있는 파일과 완료 확인 방법을 정합니다. 명령은 승인된 개발 작업의 검증 단계에서 실행됩니다.
              

              검증 명령
              명령을 가져오면 현재 검증 목록을 바꿉니다. 실제 프로젝트의 package scripts·테스트 도구에 맞게 확인해주세요.
              바뀐 모듈만 실행하면 변경 없는 모듈의 명령은 건너뛰고 결과에 "건너뜀"으로 남깁니다. 기준은 작업 시작 시점 커밋과의 차이입니다.
              로컬 완료는 검증과 코드 검토를 마친 작업을 이 컴퓨터의 기본 브랜치에 빠른 병합(fast-forward)으로 반영합니다. 원격 push는 직접 진행합니다. GitHub PR·CI 검사는 PR을 만들고 저장소에 등록한 필수 CI 검사가 통과해야 완료됩니다. 저장한 뒤 승인하는 작업부터 적용됩니다.
              AI가 쓰는 모든 글(커밋 메시지, PR 제목·본문, 문서, 단계별 결과, Studio 명세서·목업)을 이 언어로 씁니다. 커밋 메시지는 개발 역할의 AI가 직접 작성하고, 비어 있거나 안전하지 않으면 작업 제목을 씁니다. 코드·명령·경로는 그대로 둡니다. 저장한 뒤 승인하는 작업부터 적용됩니다.
              

              수정안 적용 범위
              Test Automation·Tech Writer는 파일을 직접 쓰지 않고 수정안을 냅니다. 수정안은 아래 경로와 모듈 수정 허용 경로가 겹치는 곳에만 적용됩니다.
              승인된 위키 항목으로 만든 Markdown 열람본이 생성되는 위치입니다. 프로젝트 최상위 폴더 기준 상대 경로이며, 비우면 docs/wiki를 씁니다. 위키 정본은 프로젝트 DB입니다.
              미리보기 서비스 (선택)
              변경 검토 화면에서 실제 개발 화면을 캡처할 로컬 서비스입니다. 실행 명령은 실행파일과 인수만 입력하고, 주소는 이 컴퓨터(127.0.0.1)와 DevRoster 화면과 다른 포트만 사용합니다. 저장한 뒤 승인하는 작업부터 적용됩니다.
              예상 비용 (선택)
              직접 입력한 가격표로 AI 실행 비용을 추정합니다. 실제 청구액이나 구독 잔여량이 아니며, 기본은 예산 비율에 도달해도 알림만 남깁니다. 비워두면 비용을 계산하지 않습니다.
              가격표에 없는 모델의 호출은 비용을 알 수 없어 합계에 들어가지 않습니다. 저장한 뒤 승인하는 작업부터 적용됩니다.
              

              실행 예산·웹 포트
              포트는 다음 서버 실행부터 적용합니다. 명령의 --port 옵션을 지정하면 그 값을 우선합니다.
              

              05
              환경변수와 선택 연동
              API 키·DB 연결 주소처럼 프로젝트에 필요한 값을 입력하세요. 저장한 값은 다시 표시하지 않습니다.
              기존 마스크는 값을 유지합니다. 행을 삭제하고 저장하면 해당 변수가 삭제됩니다. 승인 작업에는 이름만 기록하고, 실제 값은 실행할 때 로컬에서 읽습니다.
              

              어떤 환경을 추가할 수 있나요?
              인증 값을 저장한 뒤 외부 도구 연결에서 MCP의 범위와 허용 기능을 선택하고 실제 읽기를 검사하세요. 화면 자료는 Stitch·Figma 참고 자료에서 Studio·Workflow에 연결할 수 있습니다. 앱 서버 환경은 앱 실행 설정에도 연결해야 합니다.
              

              06
              준비 상태 확인
              저장된 설정을 기준으로 폴더·Git·CLI·로그인·개발 도구를 확인합니다. 검사만으로 개발을 실행하지 않습니다.
              설정을 저장한 뒤 진단하면 다음에 할 일을 볼 수 있습니다.
              이제 시작해 보세요
              로그인이 필요하다고 나오면 AI 도구에서 앱 전용 로그인을 먼저 마칩니다. 그다음 Studio에서 기획서를 쓰고 명세·화면을 만듭니다.
              Studio에서 기획 시작 AI 도구 로그인 프로젝트 홈
              터미널에서 여는 명령
              개발 실행·배포는 기존 승인 흐름에서 별도로 활성화합니다. Git 초기화·초기 commit은 사용자가 준비하고, Git 구조를 바꿨다면 설정을 다시 저장해주세요.
